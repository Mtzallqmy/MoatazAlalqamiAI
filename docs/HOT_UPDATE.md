# نظام التحديثات الديناميكية (Hot Update / Remote Config)

نظام يتيح إضافة ميزات وتحديثات إلى التطبيق **دون الحاجة لعمل release جديد** إلا للأشياء التي تتطلب كودًا جديدًا أو مكتبات أصلية (native binaries) لا يمكن أن توجد مسبقًا في التطبيق.

## كيف يعمل

1. عند فتح التطبيق، يجلب `RemoteConfigService` وثيقة JSON من `remote-config/config.json` في المستودع (GitHub raw URL).
2. تُخزَّن آخر نسخة صالحة محليًا في الإعدادات المشفرة وتُحدَّث كل 6 ساعات (قابلة للتعديل).
3. التعديل محليًا: عدّل `remote-config/config.json` وارفعه عبر git push — الجميع سيستلمون التحديث خلال 6 ساعات أو فورًا عبر Settings → Check for updates.
4. إذا كانت النسخة المبنية في التطبيق أقدم من `min_app_version` في الوثيقة، تُتجاهل كل المحتويات ما عدا الإعلان.
5. الوثيقة تُصادَق عليها parse-time: المعرّفات غير الصالحة، الأحجام الزائدة، وأنواع الأدوات غير المسموحة تُستبعد تلقائيًا (fail-closed إلى الإعدادات المدمجة).

## ما يمكن تحديثه عن بُعد (بدون APK)

| المحتوى | الوصف |
|---|---|
| `feature_flags` | مفاتيح ميزات تفعّل قدرات موجودة مسبقًا في الكود |
| `prompt_additions` |_presets_ دردشة جديدة تظهر في الاختيار |
| `persona_additions` | شخصيات/أدوار جديدة للنماذج |
| `dynamic_tools` | تعريفات أدوات جديدة (schema + routing) تُنفَّذ على executors مدمجة فقط |
| `system_prompt_append` | نص يُلحق بـsystem prompt للدردشة |
| `announcement` | إعلان يظهر مرة واحدة في التطبيق |

## ما يتطلب release جديدًا (لا يمكن تجاوزه)

- كود تنفيذي جديد (خوارزميات، UI جديد كليًا، executors جديدة للأدوات الديناميكية)
- مكتبات أصلية أو binaries (proot, OpenCode)
- تغييرات على البنية المخزنة التي تحتاج migrations

## الأمان

- **لا تنفيذ كود عن بُعد**: الأدوات الديناميكية من نوع `builtin` فقط تُنفَّذ (على executors موجودة في الـAPK)، ونوع `webhook` اختيارى للمستخدم مع token خاص به.
- **Version gating**: التطبيقات القديمة لا تُطبَّق عليها تهيئة إصدارات أحدث.
- **Fail-closed**: وثيقة فاسدة أو خبيثة تُتجاهل وتبقى النسخة السابقة.
- **Validation**: معرّفات بأحرف آمنة، حدود حجم للنصوص (8000 حرف)، أنواع معلمات مقيدة.

## كيفية الاستخدام (للمطور)

```json
{
  "version": 2,
  "min_app_version": "3.7.0",
  "feature_flags": { "my_new_feature": true },
  "prompt_additions": [
    { "id": "code_reviewer", "title": "مراجع الأكواد", "text": "راجع الكود بدقة وأشر إلى..." }
  ],
  "dynamic_tools": [
    {
      "id": "custom.summary",
      "name": "summarize",
      "description": "Lخص النص المعطى.",
      "parameters": { "text": { "type": "string", "required": true } },
      "kind": "builtin",
      "built_in": "terminal.echo",
      "timeout_seconds": 30
    }
  ]
}
```

لتفعيل ميزة تجريبية جديدة في الكود: أضف قراءة `FeatureFlags.isOn(config, "my_new_feature")` عند نقطة القرار، واتركها `false` افتراضيًا. لا تُنشر وثيقة remote إلا داخل envelope موقّع وبمفتاح عمومي مثبت في الـAPK.

## التوقيع الرقمي للمستندات (Signed Manifests)

إضافة فوق نظام Hot Update: يمكن الآن تغليف وثيقة `config.json` في envelope موقع رقميًا بصيغة Ed25519 (format: `ma-remote-manifest-v1`)، والتطبيق يتحقق من التوقيع تلقائيًا عند استلام وثيقة موقّعة. القواعد:

| الحالة | الوضع LAX (هجرة legacy صريحة فقط) | الوضع STRICT (الافتراضي) |
|---|---|---|
| وثيقة عادية بدون envelope (legacy) | مقبولة | مرفوضة |
| envelope بدون توقيع | مقبول (فترة ما قبل تثبيت المفتاح) | مرفوض |
| envelope بتوقيع غير صالح | مرفوض نهائيًا | مرفوض نهائيًا |
| envelope بتوقيع صحيح ومفتاح مثبت | مقبول (المصادقة الكاملة) | مقبول |

المفتاح العمومي يُثبَّت من داخل التطبيق (يُمرَّر إلى `RemoteManifestVerifier.pinPublicKeyHex(...)` عند الإقلاع). غياب المفتاح أو التوقيع يفشل مغلقًا، والمفتاح السري يبقى في بيئة إصدار محمية ولا يدخل المستودع أو APK.
